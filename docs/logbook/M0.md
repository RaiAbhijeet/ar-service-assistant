# M0 — Foundations

## The stack

**Headset (Meta Quest 3S):** Unity 6, built on OpenXR — not Meta's legacy Oculus XR
plugin, which is an explicit project constraint — with Meta's XR SDK layered on top
for passthrough and Quest-specific features (the Passthrough Building Block).
Talks to the edge server over WebSocket on the local WLAN.

**Edge server (Windows, via WSL2 + Docker Desktop):** two containers, `api`
(FastAPI) and `db` (Postgres + pgvector), plus Ollama running natively on
Windows, outside Docker. Everything is LAN-only; nothing leaves the network.

## Why Ollama runs natively, not in a container

Docker can pass a GPU through to a container — WSL2/NVIDIA support makes that
possible — but it's an extra compatibility layer this single-box edge deployment
doesn't need. Running Ollama directly on Windows gives it the GPU with nothing
in between, which is what matters for inference latency.

## What `host.docker.internal` does

Inside a container, `localhost` refers to the container itself, not the Windows
host — so the `api` container can't reach Ollama at `localhost:11434`.
`host.docker.internal` is a special DNS name that Docker Desktop resolves to the
real host machine's IP from inside the container's isolated network. That's how
`api` actually reaches Ollama.
